# Test and fuzz status

*2026-09-08. Everything below was executed, not planned.*

## Unit and integration tests

**59 pass, 0 fail** (`cargo test`): 50 unit + 9 ETSI-014 integration. Clippy clean.

Up from 39 before the anomaly detector was wired. The 20 new tests exist because wiring a
detector into the key-delivery path **increases the attack surface**, and each one pins a property
that surface needs.

### Signature safety

The appliance's Falcon key signs both handshake transcripts and anomaly alerts, so the two uses
share a signing oracle unless separated.

| Test | Property |
|---|---|
| `signing_bytes_always_carry_the_domain_tag` | Alerts carry `PQTG-ANOMALY-ALERT-v1\0` |
| `an_alert_can_never_be_confused_with_a_transcript_hash` | Alert bytes exceed 32 and the tag contains a NUL |
| `length_prefixing_makes_serialisation_injective` | Two different alerts cannot serialise identically |
| `the_signature_covers_the_window_not_just_the_score` | Editing the telemetry invalidates the signature |
| `tampering_with_the_score_breaks_the_signature` | A downgraded score fails verification |
| `alert_signature_verifies_against_the_appliance_identity` | A verifier can confirm provenance |

### Fail-closed loading

An untrained ternary net scores noise. A detector that cries wolf is worse than none, so absence
must be an error the caller handles by disabling detection.

`load_fails_loudly_on_a_missing_file`, `load_fails_loudly_on_garbage`,
`model_survives_save_and_load`.

### Hostile and degenerate telemetry

A KME under attack can report anything. Scoring must stay total.

| Test | Property |
|---|---|
| `degenerate_telemetry_never_panics_and_never_yields_nan` | NaN, ±∞, negatives, 1e30 all stay finite and in range |
| `score_is_always_a_probability` | Output in [0,1] across pseudorandom windows |
| `a_short_window_scores_without_panicking` | Every window length below the full size |
| `the_window_is_bounded_no_matter_how_long_it_runs` | 10,000 samples, memory flat |
| `monitor_stays_quiet_until_the_window_is_full` | No score before enough evidence |
| `a_threshold_above_one_can_never_fire` | An unreachable threshold means off, not always-on |

### Config safety

| Test | Property |
|---|---|
| `a_config_without_an_anomaly_section_still_parses` | **Deployed appliances survive upgrade** |
| `detection_is_off_by_default` | Safe default |
| `enabling_without_a_model_path_is_expressible_and_means_disabled` | No untrained fallback |
| `a_zero_sample_every_cannot_cause_a_division_by_zero` | Guard exercised, not assumed |
| `a_threshold_outside_zero_to_one_still_parses_and_means_never_fire` | Operator-proofing |

**3.44 million executions, zero crashes, zero artifacts.**

`anomaly_model` fuzzes the module's two untrusted inputs: arbitrary bytes as a model file (an
attacker who can write `model_path`, or a corrupted disk, must not cause a panic or an allocation
bomb, hence the window-size guard), and arbitrary bytes as telemetry.

Reproduce:
```

```

## Attack surface added by the detector, and what closes it

| Risk | Mitigation | Where |
|---|---|---|
| Shared signing oracle with the handshake | Domain tag + length prefixing | `ALERT_DOMAIN`, tests above |
| A hanging KME status poll stalls key delivery | 250 ms timeout, sample dropped | `ANOMALY_POLL_TIMEOUT_MS` |
| One mutex serialises every key request | `try_lock`, drop the sample under contention | `observe_control_channel` |
| Alert spam burns CPU (~326 µs Falcon each) and grows the audit log | 30 s minimum interval, compare-and-swap so concurrent connections cannot both pass | `MIN_ALERT_INTERVAL_SECS` |
| An untrained model emits false alerts | No load-or-default; failure disables detection | `init_anomaly_monitor` |
| Detection failure blocks key service | Observation is advisory; poll errors are skipped, never propagated | `observe_control_channel` |

## Still open

- **No trained model ships with the repo**, so the feature is present and correctly disabled. The
  training binary is uncommitted in the public mirror and should move here.
- Fuzzing runs were 45–90 s each. Before any release, run each target for an hour and commit the
  corpus.
- `cargo-fuzz` is pinned to 0.12.0 by the toolchain. Updating rustc past 1.91 would allow current.
